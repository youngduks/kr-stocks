# 공정 영상 만들기

원료 → 중간재 → 부품으로 이어지는 제조 공정을, 보는 사람이 "이 단계에서 원자재가 어떤 모습이고 어떤 설비로 바뀌는가"를 한눈에 이해하도록 만드는 HTML 페이지다. 실제 동영상 파일이 아니라 캔버스 애니메이션과 플레이어로 된 페이지이며, Artifact로 게시한다.

검증된 엔진(플레이어·자막·단계별 정지·한국어 줄바꿈·테스트 훅)은 `assets/player-template.html`에 있다. 새 부품마다 쓰는 것은 세 파일뿐이다:

| 파일 | 내용 |
|---|---|
| `meta.json` | 제목, 머리글, 소개문, 업스트림/다운스트림 라벨, 하단 주의 문구, 게시 설명 |
| `scenes.js` | 장면 그리기 함수들 + 공정 데이터 배열 `const S=[...]` |
| `sections.html` | 단계 목록 아래의 "설비 검토" 섹션들(설비표, 방식 비교, 검토 의견, 참고 자료) |

완성 예제(EV 구동모터용 NdFeB 영구자석, 15개 장면, 자석 중량·원가 계산기 포함)가 `references/example-ndfeb/`에 있다. 처음 만들 때는 예제의 `scenes.js` 앞부분과 `S` 배열, `sections.html` 구조를 먼저 훑어보고 시작하면 빠르다.

## 작업 순서

### 1. 범위 정하기
부품, 용도(예: "EV 구동모터용"), 출발점(광석·원유·원면 등), 끝점(부품 단품인지 조립까지인지)을 정한다. 요청에 없으면 업계에서 가장 흔한 범위로 정하고 답변에 밝힌다. 업스트림(원료·제련)과 다운스트림(부품 제조)의 경계도 정한다. 이 경계가 진행 바와 단계 번호 색을 나눈다.

### 2. 공정 조사
본 공정을 8–12단계로 나눈다. 단계마다 정리할 것:
- 공정명, **산출 원자재 형태**(이름 + 상태·크기·순도 같은 한 줄 설명), 핵심 수치 칩 3–4개
- **주요 설비**(캡션에 한 줄), 품질·원가를 좌우하는 **관리 포인트**(설비표용)
- 자막 해설 1–2문장

공정 **순서**는 실제 산업 순서와 맞는지 반드시 확인한다. 순서가 틀리면 전문가인 사용자에게 바로 신뢰를 잃는다. 이 스킬을 만들 때 실제로 지적받은 예: IPM 로터용 자석은 "착자 후 조립"이 아니라 미착자 상태로 삽입·고정한 뒤 **로터째 착자**한다. 조립·열처리·코팅·검사의 앞뒤 관계는 특히 의심하고 검색으로 확인한다.

수치는 업계 일반 범위로 쓰고(예: "~1,050 ℃", "3–5 μm"), 확신이 없는 수치나 비교 평가는 웹 검색으로 확인한다. 확인 못 한 것은 페이지와 답변에 "일반적 경향", "공개 자료 부족"이라고 적는다. 모르는 용어(예: 사용자가 말한 낯선 코팅 이름)는 추측해서 넣지 말고 확인한 것만 넣은 뒤 정확한 표기를 묻는다.

### 3. 심화 장면과 비교 섹션
사용자가 설비 방식 차이(배치로 vs 연속로, 도포 방식, 코팅 종류 등)를 물으면 세 가지를 같이 만든다.
1. 해당 단계 바로 뒤에 **심화 장면**(`no:'09B'`, `'10C'`처럼 번호+알파벳). 분할 화면 비교나 방식별 타일 격자.
2. `sections.html`에 **비교표**(항목 × 방식)와 방식별 **장단점 카드**.
3. **검토 의견**에 선택 기준(물량, 등급 수, 형상, 원가 변수)과 확인이 필요한 점.

형식은 `references/content-guide.md`를 따른다.

### 4. 프로젝트 파일 작성
scratchpad에 프로젝트 폴더를 만들고 세 파일을 쓴다.
- 장면 그리기 규칙, 헬퍼 함수, 레이아웃 금지 구역, 장면 패턴은 `references/scene-cookbook.md`에 있다. 장면을 쓰기 전에 읽는다.
- `S` 항목 형식:
  ```js
  {no:'03', d:9, draw:s3, kind:'up', name:'침출·침전', form:'혼합 희토류 탄산염',
   detail:'습윤 침전물(케이크)', chips:['황산 배소 → 물 침출','RE₂(CO₃)₃'],
   eq:'로터리 킬른 · 교반 침출조 · 필터프레스',
   narr:'정광을 진한 황산으로 배소하고 물로 침출하면 …'}
  ```
  `kind`는 `'up'`·`'down'`·`'sum'`(마지막 요약 장면). 본 단계 `no`는 숫자만(`'01'`), 심화 장면은 `'09B'`처럼 쓴다. HUD의 "/ N"은 숫자만인 단계 수로 자동 계산된다. `d`는 장면 길이(초)이며 9초가 기본이다.

### 5. 빌드와 확인
```bash
python3 <skill>/scripts/build.py <project_dir> <out.html>
node <skill>/scripts/check.js <out.html> <shots_dir>
```
`check.js`는 장면마다 두 장을 저장한다. `scene-NN.png`는 70% 시점(애니메이션 중간), `scene-NN-stop.png`는 단계별 정지 때 실제로 멈추는 프레임(`d-0.35`초)이다. 정지 프레임은 6장씩 묶은 `sheet-N.png`로도 만든다. 그 밖에 데스크톱·휴대폰 플레이어 스크린샷을 저장하고, 단계별 정지 동작, 휴대폰 가로 넘침, 스크립트 오류를 보고한다. 먼저 `sheet-*.png`로 정지 화면의 글자 겹침, 잘림, 빈 화면을 보고, 필요하면 `scene-NN.png`로 중간 상태(교차 페이드 중 겹침)를 확인해 한 번에 고친다. 확인은 한 차례만 하고 게시한다. 사용자가 기다리고 있다.

### 6. 게시와 보고
Artifact 도구로 게시한다. 첫 게시 때는 `icon`(예: "factory")과 한 문장 `description`을 넣고, 이후 수정은 같은 파일 경로로 다시 게시한다. 템플릿은 Artifact 페이지 계약(테마 토큰, 안전 영역, 폰트, CDN 제한)을 이미 지키므로 별도 디자인 작업은 필요 없다.

답변에는 다음을 짧게 쓴다: 무엇을 담았는지(장면 목록 표), 확인한 것, 확인하지 못한 것과 그 이유, 출처 링크.

## 사용자 피드백에서 나온 원칙

이 스킬의 원본을 만들며 실제로 받은 지적이다. 템플릿이 대부분 처리하지만, 새 장면과 문구를 쓸 때도 지킨다.

- **영상 화면을 가리지 않는다.** 버튼·안내·오버레이를 캔버스 위에 띄우지 않는다. 단계 버튼은 템플릿이 영상 아래 줄에 둔다. 장면 안의 라벨끼리도 겹치지 않게 배치한다.
- **기본은 단계별 정지.** 한 공정 설명이 끝나면 멈추고, "이 단계 다시 보기 / 다음 단계" 버튼으로 넘어간다. '연속 재생'으로 바꾸면 끝까지 이어진다. 템플릿 기본값을 바꾸지 않는다.
- **한국어 줄바꿈과 띄어쓰기.** 템플릿은 단어 중간에서 줄을 바꾸지 않고(`keep-all`), 숫자와 단위를 붙인다. 문장은 맞춤법과 띄어쓰기를 검토한다("수%", "1,050 ℃", "그다음"). 캔버스 텍스트는 자동 줄바꿈이 없으니 한 줄을 짧게 쓰고 줄을 나눠 배치한다.
- **정확성이 디자인보다 먼저다.** 공정 순서, 설비 이름, 수치를 사용자는 현업 지식으로 검토한다. 확신이 없으면 검색하고, 출처를 페이지의 "참고 자료"와 답변에 남긴다.
- **비교에는 장단점과 선택 기준까지.** 방식을 나열만 하지 말고 언제 무엇을 고르는지 판단 기준을 쓴다.

- `references/content-guide.md`: 원자재 형태·설비·관리 포인트 작성법, 설비표·비교표·장단점 카드·검토 의견 마크업, 단위·문체 규칙
- `references/example-ndfeb/`: 완성 예제 프로젝트(그대로 빌드 가능). `sections.html` 맨 앞에 계산기 섹션 예가 있다
