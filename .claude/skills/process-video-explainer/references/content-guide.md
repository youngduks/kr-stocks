## 1. 단계 데이터 쓰기

| 필드 | 쓰는 법 | 예 |
|---|---|---|
| `name` | 공정명, 6–10자 | `분쇄·선광` |
| `form` | **이 단계의 산출 원자재** 이름. 캡션의 큰 제목 | `희토류 정광` |
| `detail` | 상태·크기·순도를 한 줄로 | `고운 분말 · 입도 ~75 μm 이하` |
| `chips` | 핵심 수치·화학식·공법 키워드 3–4개 | `['REO 50–70%','부유선별']` |
| `eq` | 주요 설비를 ` · `로 나열. 공정 흐름 순서대로 | `조 크러셔 · 볼밀 · 부유선별기` |
| `narr` | 자막 해설 1–2문장. "무엇을 하면 → 무엇이 된다" | `원광을 잘게 부순 뒤 … 정광 분말이 됩니다.` |

- 원자재 형태가 이 영상의 축이다. 단계마다 형태가 실제로 바뀌는지(광석 → 분말 → 용액 → 침전물 → 산화물 → 금속 → 박편 …) 확인하고, 바뀌지 않는 단계는 앞뒤 단계와 합친다.
- 심화 장면(`'09B'`)의 `form`에는 비교 대상을 쓴다(`배치식 vs 연속식`).
- 요약 장면(`kind:'sum'`, `no:'—'`)은 마지막에 하나 둔다.

## 2. meta.json

```json
{
  "title": "원광에서 자석까지",
  "eyebrow": "EV 구동모터 · NdFeB 소결자석",
  "lede": "…따라가는 약 2분 분량의 애니메이션입니다. 기본은 단계마다 멈추는 방식이고, 플레이어의 ‘연속 재생’을 누르면 끝까지 이어서 재생됩니다.",
  "kinds": {"up": "업스트림 · 채광·제련", "down": "다운스트림 · 자석 제조"},
  "summary_label": "요약",
  "note": "수치는 일반적인 산업 범위를 단순화한 값이며 …",
  "description": "게시용 한 문장 설명"
}
```
- `title`은 2–4어절의 이름으로 짓는다. "원료에서 OO까지" 같은 형태가 잘 맞는다. 설명은 `lede`와 `description`에 넣는다.
- `lede`에는 영상 길이(장면 수 × 9초)와 재생 방식 안내를 넣는다.
- `description`은 Artifact 게시 때 `description` 인자로 쓴다.

## 3. sections.html 구성과 마크업

순서: ① 공정별 주요 설비 → ② 이후 사용자가 요청한 비교 섹션들 → 검토 의견 → 참고 자료. 각 섹션의 뼈대:

```html
<section class="deep" aria-labelledby="eqTitle">
  <p class="eyebrow">설비 검토 ①</p>
  <h2 id="eqTitle">공정별 주요 설비</h2>
  <p>한두 문장 소개</p>
  <div class="tbl"><table>
    <thead><tr><th>단계</th><th>산출 원자재</th><th>주요 설비</th><th>관리 포인트</th></tr></thead>
    <tbody><tr><td class="k">01 채광</td><td>…</td><td>…</td><td>…</td></tr></tbody>
  </table></div>
</section>
```

쓸 수 있는 클래스(템플릿 CSS에 정의됨):
- `.tbl` 표 감싸기(휴대폰에서는 표 안에서만 가로 스크롤). `td.k` 굵은 첫 열, `td.c` 가운데 정렬, `td.mono` 고정폭 수치
- `.meter` 정성 평가 점: `<span class="meter" title="중">●●<span class="off">●</span></span>`. 표 아래에 범례 `<p class="note">●●● 좋음 · ●●○ 보통 · ●○○ 불리 …</p>`
- `.cards` > `article.card`: 방식별 카드. 안에 `h3`, `.tagline`, `dl` > `div` > `dt`/`dd`. 장점은 `div.pro`, 단점은 `div.con`
- `ol.flow` 공통 공정 흐름(항목 사이에 화살표가 자동으로 붙음)
- `section.deep.review` 안의 `ol` > `li` > `b`(판단 기준 한 줄) + 설명
- `section.deep.sources` 안의 `ul` > `li` > `a[target=_blank][rel=noopener]`
- `.eyebrow`, `h2`, `h3`, `p.note`

### 비교표 행 템플릿 (설비 방식 A vs B)
구조 / 운전 방식 / 생산성 / 에너지 / 품질 균일성 / 유연성(품종 전환) / 투자·면적 / 운영 리스크 / 적합한 경우. 해당 없는 행은 빼고, 그 설비에만 있는 쟁점(예: 탈지, 확산원 손실)은 추가한다.

### 방식별 카드 템플릿
설비(구성 장비) / 공법(무엇을 어떻게) / 장점 3개 / 단점 3개 / 적합(형상·물량·등급). 평가가 확실하지 않은 방식은 제목에 "(참고)"를 붙인다.

### 검토 의견
4–7개. 각 항목은 굵은 한 줄 판단 기준 + 근거 1–2문장. 원가를 좌우하는 변수, 형상·물량에 따른 1차 선별, 공개 연구 수치(출처 있는 것만), 확인이 필요한 점(장비사 보증치·실측 데이터)을 포함한다.

### 계산기 섹션 (선택)
사용자가 치수·특성·사용량으로 중량이나 원가를 계산하고 싶어 하면 `sections.html`에 계산기 섹션을 넣는다. 예제는 `references/example-ndfeb/sections.html` 맨 앞의 "자석 중량·원가 계산기"(입력 폼 + 결과 카드 + 원가 구성 막대 + 민감도 표 + 자체 `<style>`·`<script>`)다.
- 결정적인 값(부피·중량)과 추정값(원가)을 구분해 보여 준다. 단가·조성·수율 같은 가정은 모두 입력란으로 열어 두고, 출처가 있는 값은 기준 시점과 함께 힌트에 적고, 없는 값은 "가정값"이라고 쓴다.
- 입력이 공개 범위를 벗어나면(예: 등급별 함량 한계, 공법 적용 한계) 결과 아래에 경고 문장으로 알린다.
- `build.py`는 `sections.html` 전체에 숫자·단위 붙임 치환을 하므로, `<script>` 안에 `5 mm`처럼 숫자 뒤 공백과 단위를 쓰면 `&nbsp;`가 코드에 들어간다. 스크립트에서는 `'\u00a0'`으로 공백을 넣고, 빌드 후 스크립트 안에 `&nbsp;`가 없는지 확인한다.
- 색은 템플릿처럼 `:root` 토큰과 다크 모드 재정의로 넣고, 입력값 저장은 `localStorage`를 try/catch로 감싼 편의 기능으로만 쓴다.

## 4. 단위·숫자 표기

- 숫자와 단위 사이는 한 칸 띄운다: `75 μm`, `1,050 ℃`, `7.5 g/cm³`, `2 T`. 단, `%`는 붙인다: `REO 3–10%`, `수%`. 빌드 스크립트가 띄운 칸을 줄바꿈 없는 공백으로 바꾼다.
- 범위는 화면·표에서 en dash(`3–5 μm`), 자막 문장에서는 물결(`3~5 마이크로미터`)도 괜찮다. 근삿값은 `~`.
- 천 단위 쉼표: `1,080 ℃`. 화학식은 아래첨자 문자(`CO₃`, `Nd₂Fe₁₄B`, `TbF₃`)를 쓴다.

## 5. 문체

- 자막·소개는 짧은 평서문(`~합니다`). 표·카드는 명사형·개조식(`투자비 낮음`, `라인 정지로 이어짐`).
- 맞춤법과 띄어쓰기를 검토한다. 자주 틀리는 것: `그다음`(붙임), `수%`, `~할 수 있다`(띄움), 단위 앞 띄어쓰기.
- 업계 용어는 한국어 표기 + 필요하면 괄호에 영문(`스트립캐스팅`, `입계확산(GBD)`).
- 같은 대상은 같은 이름으로 부른다(장면, 캡션, 표가 서로 달라지지 않게).

## 6. 정확성과 출처

- 공정 순서, 설비 이름, 대표 수치는 검색으로 확인한다. 특히 조립·열처리·코팅·검사의 순서는 먼저 의심한다.
- 정성 평가(●●○)는 "일반적 경향"이라고 표 아래에 밝힌다.
- 공개 자료가 없는 것(설비 kWh/kg 실측 비교 등)은 "공개 자료 부족, 장비사 데이터로 확인 필요"라고 검토 의견에 쓴다.
- 참고 자료 섹션에는 실제로 근거로 쓴 링크만 넣고, 내용을 확인하지 못한 링크는 넣지 않는다.
- 세션 네트워크 정책 때문에 원문(특허 PDF, 학술지, 제조사 페이지)을 열지 못하고 검색 결과 요약만 본 경우가 있다. 그때는 요약이 그 링크를 명시적으로 가리킬 때만 링크를 남기고, 답변의 "확인 못 한 것"에 "원문 미확인(검색 요약 기준)"과 막힌 도메인을 적는다. 요약에 수치가 있어도 어느 문서의 것인지 특정되지 않으면 링크 없이 "업계 의견", "공개 연구"처럼 출처 성격만 밝힌다.
- 특허 청구 범위의 수치(예: 두께 구간별 철손 상한)는 실제 등급표가 아니라고 페이지에 밝힌다.
