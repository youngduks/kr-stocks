## 보이스노트 (`/voicenote`)

회의를 녹음하면서 실시간으로 **자막 · 번역 · 회의록**을 만드는 단일 HTML 앱.
한국어로만 하는 회의(번역 없음)와 한국어 ↔ 영어·일본어·중국어를 섞어 쓰는 회의를 지원한다.
주식 사이트와 코드를 공유하지 않는 독립 도구이고, 이 사이트는 HTTPS 호스팅만 빌려준다
(마이크는 HTTPS에서만 열린다). 검색 노출은 막아 두었다.

- 파일: `public/voicenote/index.html` + `rules.js` — 외부 라이브러리 없음
- 주소: `/voicenote` (`next.config.mjs`의 rewrite)
- **서버 없음. 사용자가 자기 Gemini 무료 키를 한 번 넣으면 브라우저가 Gemini를 바로 부른다.** 운영 비용 0원.
  키는 그 브라우저(localStorage)에만 저장되고 `x-goog-api-key` 헤더로만 나간다.
- PC 크롬, 아이폰·아이패드 Safari, 안드로이드 모두 같은 방식으로 동작한다.

### 쓰는 법

1. https://aistudio.google.com/apikey 에서 구글 로그인 → API 키 만들기 → 복사
2. `/voicenote` 첫 화면 칸에 붙여넣고 저장 (처음 한 번만)
3. 회의 언어(‘한국어만’ 또는 한국어 ↔ 영어·일본어·중국어)를 고르고 **녹음 시작** → 끝나면 **종료** → Gemini가 회의록을 쓴다
4. (선택) ‘참석자·용어’ 칸에 이름·사내 용어를 적어 두면 그 표기로 받아쓴다 — 한국어 회의에서 가장 자주 틀리는 것이 사람 이름과 용어다

### 동작 방식

| 단계 | 방식 |
|---|---|
| 녹음 | 마이크 하나를 MediaRecorder(녹음 파일)와 음성 조각 추출이 같이 쓴다. 소리는 AudioWorklet(오디오 전용 스레드)에서 받고, 브라우저의 소음 억제·반향 제거는 끈다(설정에서 켤 수 있음). 녹음은 15초마다 IndexedDB에 내려 적어서 탭이 죽어도 그 직전까지 되살아난다 |
| 실시간 자막 (+ 번역) | 약 20초(설정 ‘자막 간격’) 단위로 말이 끊기는 곳에서 16kHz WAV 조각을 자른다. 보낼 때는 **바로 앞 조각들의 음성(최대 45초)을 같이 보내고** 그 구간의 자막을 새 결과로 바꿔 끼운다(문맥 창). 한 번의 호출로 받아쓰기·언어 판별·번역을 JSON으로 받는다 |
| 정밀 받아쓰기 + 화자 구분 | 종료하면 **녹음 파일 전체를 한 번에** Gemini(Flash)에 보내 다시 받아쓴다. 목소리로 사람을 구분해 ‘화자 1, 화자 2…’를 붙이고, 자막을 이 결과로 바꾼다(실시간 자막 원본은 백업에 남김). 이름표를 누르면 이름을 붙일 수 있고 회의록에도 반영된다 |
| 참석자·용어 (선택) | 이름·사내 용어 표기를 받아쓰기와 회의록에 참고로 전달 |
| 녹음 중 정리 | 처음에는 규칙 기반(`rules.js`, 지연 0). 1분쯤 뒤부터 2~3분마다 Gemini 초안으로 바뀐다(설정에서 끌 수 있음) |
| 회의록 | 화자가 붙은 녹취록 전체를 Gemini에 한 번 보내 개요·배경·주요 논의·결정 사항·향후 계획(할 일·담당·기한 / 일정)·미결 사항·키워드를 받는다 |
| 키가 없을 때 | 브라우저 음성 인식(Web Speech)으로 녹음·자막만 |

### 받아쓰기 정확도 — 실제 호출로 재고 정한 것 (2026-11-22)

"한국어 인식률이 매우 떨어진다"는 실사용 피드백을 받고, 3명이 번갈아 말하는 95초짜리 한국어 회의 합성음(정답 대본 있음)으로
실제 Gemini 무료 키에 물려 쟀다. 합성음(espeak)이라 사람 목소리보다 어렵지만, 같은 음성끼리의 비교는 유효하다.

| 모델 | 20초 조각 | 45초 | 100초(전체) | 화자 구분(전체) |
|---|---|---|---|---|
| `gemini-3.5-flash-lite` (별칭 `flash-lite-latest`) — 고치기 전에 쓰던 모델 | 글자 오류율 40% | 23% | 28% | 3명 중 2~3명, 44~50% 정확 |
| `gemini-3.1-flash-lite` | **13%** | **6%** | **4%** | 2명, 60~71% |
| `gemini-3.5-flash` | — | — | 6% | 3명, 85% |
| `gemini-3.6-flash` | — | — | **4~5%** | **3명, 92~94%** |
| `gemini-3.7-flash`·`3.8-flash`·`flash-latest` | 음성 입력에는 90초쯤 뒤 빈 응답(`finishReason: OTHER`) | | | |

여기서 나온 설계:

- **"최신 별칭 먼저"를 버렸다.** 음성을 듣는 일은 잰 결과대로 고른다 — 실시간 자막은 3.1 Lite, 정밀 받아쓰기는 3.6 Flash → 3.5 Flash → 3.1 Lite
  (`Gemini.PREFER`). 새 모델이 나오면 다시 재서 고칠 것. 글만 다루는 회의록은 최신 Flash를 그대로 쓴다.
- **길게 들을수록 정확하다**(13% → 6% → 4%). 그래서 실시간은 앞 조각 음성을 덧붙여 보내고(요청 수는 그대로), 종료 후에는 녹음 전체를 한 번에 보낸다.
- **화자 구분은 통째로 들어야 된다.** 20초 조각마다 따로 구분하면 조각 사이에 번호가 맞지 않는다. 녹음 전체를 한 요청으로 보내면 번호가 끝까지 유지된다.
  Flash는 하루 한도가 적지만(수십 회) 회의 하나에 한두 번만 쓰므로 충분하다.
- **빈 응답·과부하(503)·없는 모델·하루 한도 소진이면 다음 모델로 넘어간다.**
- 정밀 받아쓰기 출력은 JSON이 아니라 `[분:초] 화자N: 말 ⇒ 번역` 줄 형식 — 긴 회의에서 출력이 끊겨도 받은 줄까지는 쓸 수 있고,
  "앞에서 쓴 화자 번호 그대로 [분:초] 다음부터 이어서"라고 다시 요청하면 번호가 유지된 채 이어진다(확인함).
- 녹음 파일은 브라우저가 만든 그대로(webm/opus 24kbps, 사파리는 mp4) 보낸다 — Gemini가 두 형식의 내용을 정확히 읽는 것을 확인했다.
  약 13MB(1시간 남짓)까지는 요청에 실어 보내고, 더 크면 Files API로 올린다.
- 이어서 녹음한 파일은 따로 받아쓰므로 화자 번호가 새로 매겨진다(뒤 번호로 민다). 같은 사람이면 같은 이름을 붙이면 된다.

### 무료 한도에 맞춘 설계

Gemini 무료 한도는 **모델마다 따로, 하루 요청 횟수**로 걸린다. 2026년 10월 기준 알려진 수치는 Flash-Lite 계열 하루 약 500회,
Flash 계열 하루 약 20회 수준이다(Google이 공식 표를 내지 않고 수시로 바꾼다 — 정확한 값은 AI Studio의 한도 화면에서 확인).
한도는 미국 태평양 시간 자정(한국 오후 4~5시)에 초기화된다.

- **모델을 용도별로 나눠 쓴다.** 받아쓰기·녹음 중 초안은 Flash-Lite 계열만, 종료 후 회의록은 Flash 먼저(없으면 Flash-Lite).
  받아쓰기가 Flash의 적은 한도를 먹어 회의록을 못 만드는 일이 없다.
- **모델 이름은 키를 저장할 때 모델 목록(`GET /v1beta/models`)에서 받아 온다.** 별칭(`-latest`) → 새 버전 순.
  키 확인도 이 호출로 하므로 생성 한도를 쓰지 않는다. 목록은 일주일마다 새로 받는다.
- **한 모델이 하루 한도를 다 쓰면(429 + `PerDay` quotaId, 또는 `limit: 0`) 그날은 건너뛰고 다음 모델로 넘어간다.**
  분당 한도(429)는 `retryDelay`만큼 기다렸다 같은 조각을 다시 보낸다.
- **전부 소진돼도 녹음은 계속된다.** 못 받아쓴 음성 조각은 IndexedDB에 보관하고, 한도가 풀린 뒤 ‘못 받아쓴 구간 다시’를
  누르면 시간 순서대로 제자리에 끼워 넣는다(새로고침·다음 날에도 남아 있다).
- ‘보통’ 간격이면 1시간 회의에 받아쓰기 약 200회 + 초안 약 25회. 설정 화면에 오늘 사용 횟수가 보인다.
- 무료 키는 Google이 보낸 내용을 서비스 개선에 쓸 수 있다 — 화면에 안내되어 있다. 민감한 회의는 유료 결제 키를 쓰거나 키 없이 녹음만 할 것.

### 확인 범위

- **자동 테스트(Playwright, Chromium)**: Gemini API를 흉내 내고 합성 음성을 가짜 마이크로 넣어 위 동작을 전부 확인했다(85개 항목).
- **실제 Gemini 호출(무료 키, OpenAI 호환 주소)**: 앱의 지시문을 그대로 꺼내 보냈다.
  - 모델 고르기 로직을 실제 모델 목록에 돌려 후보가 맞게 나오는 것
  - 위 표의 정확도·화자 구분 측정, 번역 모드의 줄 형식(`⇒ 번역`), 끊긴 곳부터 이어 받기, webm·m4a 내용 읽기
  - 앱의 최종 정밀 받아쓰기 지시문으로 3인 회의 13차례 중 12차례의 화자를 맞히고 문장은 거의 그대로 받아씀(8초)
  - 회의록(`gemini-flash-latest`): 배경·논의·결정·할 일(담당·기한)·미결 정확, 13초. 녹음 중 초안(Lite) 1초
- **실제 호출로 찾아 고친 지시문 문제**: ① 오디오 옆에 글로 된 요청을 같이 보내면 그 요청 문장을 받아 적음 → 지시는 전부 시스템 지시문에
  ② "빠짐없이 적어라"는 안 들린 부분을 지어내게 함 → 넣지 않음 ③ "한국어로 진행되는 회의"라고만 쓰면 영어 문장을 통째로 빼먹음 → 다른 언어 문장은 그대로 적도록 명시
- **아직 확인하지 못한 것** — 이 개발 환경에서는 앱이 쓰는 기본 주소(`generateContent`·Files API + `x-goog-api-key`)로 직접 호출할 수 없었다.
  1. 녹음 파일을 `audio/webm`·`audio/mp4` 이름으로 실어 보내는 것과 Files API 올리기(브라우저에서의 CORS 포함) — 자동 테스트는 가짜 서버로만 확인.
     형식 이름이 거절되면 한 번 이름을 바꿔 다시 보내도록 해 두었다
  2. 사람이 말한 한국어에서의 정확도와 화자 구분 — 시험 음성이 합성음뿐이었다. 목소리가 비슷한 사람들, 겹쳐 말하기는 더 어려울 것이다
  3. 아이폰 Safari에서의 AudioWorklet·mp4 녹음 크기(비트레이트 설정을 따르지 않으면 파일이 커져 Files API 경로를 탄다)
